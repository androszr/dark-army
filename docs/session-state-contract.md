# Session state contract

This is the full statement of the per-session state the daemon tracks: the
categories every surface reads, what parks a turn, when a session is evicted,
what a finished session leaves behind, and the three things the daemon does to
a session on its own — auto-compact, alerts, and typing an answer into a
dialog. `CLAUDE.md` restates the invariants and names the tests; the detail
lives here.

The display-state machinery that fed the pixel-art window has been
**deleted**. What remains is the *categories*.

The daemon tracks per-session state.

## Per-session states

`registered` → `thinking` → `working` → `idle` → `confused` / `error`

## Category breakdown

`BobDaemon._activity_counts()` buckets every session into working / idle / attention via `session_stats.categorize()` — the single source of truth for the menu-bar strip (`on_activity_change`) and the panel. A session parked on a "Waiting for input" card animates as idle but belongs in attention. A `confused` session banks under attention only beside a notification card; a snag or a dismissed idle reminder with no card sleeps (22 Sep 2026) — so it is counted in no buzz's badge, raises no 30-minute `waiting` signal, admits no Live Activity and is exempt from neither staleness eviction nor the pidless grace (`test_session_stats.py`, `test_session_state.py`).

## Special events

`Notification` (idle_prompt) → confused, `StopFailure` (API error) → error. A `StopFailure`'s `error` is a **machine token** (`rate_limit`,
`billing_error`, ...), never shown raw: `stop_failure_message` (in
`protocol.py` and byte-alike in `NOTIFY_SCRIPT`) takes the terminal's own
sentence from `last_assistant_message`, else `error_details`, else the token
translated through `STOP_FAILURE_WORDS`; the token itself rides the message
and the card snapshot as `error_kind`

**Grok's permission hook is not a prompt.** Grok fires its `permission_prompt` Notification (converted to the `permission` event, nameless) for **every** tool call — its permission phase runs on each one, and an allowed tool resolves in milliseconds (`permission_resolved`, `wait_ms: 0`, in the session's own `events.jsonl`). Landed as-is it put the row in `waiting` until the next `tool_use`, so a forty-second shell command read "waiting for you" for its whole run (two Grok agents, 21 Sep 2026). `_handle_message` asks `grok_events.permission_pending` first — one tail read of `events.jsonl` on the loop, by the hook's **own** session id and cwd, before the child→parent redirect, since a child's tools are in the child's file — and a request that already has its resolution is rewritten to `permission_resolved`, an event no branch of `_update_session_state` acts on. An open request (the genuine dialog), an unreadable log or a tail with no request keeps the hook's reading. Pinned by `test_grok_events.py` and `test_session_state.py`'s `test_a_grok_permission_already_allowed_is_not_a_wait`.

An open request now mints an `answerable` row (`via="grok"`) only while Grok's log confirms it; see `docs/cli-permission-modes.md`.

## Parked turns

A `Stop`/`Notification` that is not a request for the human, suppressing **both** the card and the state. **Three reasons, asked at one site** (`_handle_message`'s `add` branch), and `StopFailure` is never parked.

`_parked_reason` is the pure pair, and stays pure: the parent is stopped on its own **live subagents**, or **nobody has prompted the session** (Claude Code fires `idle_prompt` 60s after a session goes quiet; only `UserPromptSubmit` dismisses it). `prompted` is stamped `False` by `session_start` alone and the test is `is False`, **not falsy**: a session restored from `sessions.json` carries no key and must read as prompted. `tool_use` sets it too.

`_async_subagent_reason` is the third, split off because it reads files. **`SubagentStop` is not a promise the child has finished**: for an async spawn the harness fires it when the spawning *turn* ends, seconds in, while the child works on for minutes. Measured 7 Sep 2026 on 2.1.263 — a probe told to sleep 90s left the live set after 7.6s, and `/api/state` read `subagents=1, 0, 0` while it ran. The parent's own Stop then found nothing to park on, and a session waiting on its own child sat under **Needs you** until the child returned and the next `tool_use` dismissed the card.

So `subagent_stop` keeps the **id and the moment its hook fired** on `subagents_async` (bounded by `MAX_SEEN_SUBAGENTS`, cleared by `UserPromptSubmit` with the live set, type-guarded on restore beside `subagents`) and `subagent_watch` reads the child's own transcript. **The path is composed from the session's own `transcript_path`, which the hook carries and the daemon now stores, never rebuilt from its cwd**: Claude Code mangles `.` to `-` as well as `/`, so `/Users/me/.dark-army` lives under `-Users-me--dark-army`, and a re-derived directory is silently wrong for every dotted path — a rung finding nothing reads exactly like one that is working. `session_stats._subagents_dir` is the existing seam and is reused, not copied. **It is stored before the card decision, not after**: of the ten messages the installed handler can send, only Stop, StopFailure and the idle-prompt Notification carry a `transcript_path` at all — and those three *are* the card branch. Written afterwards, the rung would read an empty string on the one turn it exists for and raise the false card anyway, so the claim is stored beside the `project` claim, early, with the same late twin for a session whose entry `_update_session_state` has only just created. Neither marks `changed`: a stored path is bookkeeping, not news.

**The reading is whether the file moved after the stop hook, and nothing about the shape of its last line.** A child that stopped *because it finished* leaves a file frozen at that instant; a child whose hook fired early because its parent's turn ended keeps writing. Measured over 8 days of this machine's own daemon logs: of 447 subagent stops matched to a transcript, **399 were frozen within ±1s of the hook** and **48 went on writing for a further 7s to 82 minutes**. Nothing landed between 1s and 7s, so `WROTE_AFTER_STOP_SECONDS` (2s) sits inside an empty band rather than on a tuned threshold.

**Why not the last record.** The harness writes **one record per content block** — a `text`, a `thinking` and a `tool_use` each on their own line, most with `stop_reason` null — so "the last record is prose" is not a terminal marker: a child narrating before its next tool call is byte-shaped like one that has answered. `"stop_reason":"end_turn"` is sound where it fires, and this rung was built on it first; it is nowhere near sufficient. Of the **1,194 finished child transcripts** on this machine, **506 (42%) carry no terminal marker on the last line at all** — Opus, Fable and Sonnet children, not one model's quirk, plus 34 `<synthetic>` `stop_sequence` endings. Freshness was then the only thing left to release them, so **every ordinary synchronous spawn would have suppressed its parent's real card for the next fifteen minutes** — this rung's own failure inverted, and at the scale of hundreds of cards a week. The markers survive as an **early release** only: `end_turn` and `[Request interrupted` never appear mid-run, so a child writing one is finished whatever its mtime says, and they can only ever let a card through sooner.

Three bounds. `STALE_SECONDS` (15 min) is the ceiling on being wrong — over the longest single tool call here (a full `pytest` run, ~7 minutes, silent while it runs), under the 30-minute `SUBAGENT_PARK_MAX_SECONDS`. Failure means **not running**: missing, unreadable, underivable, sliced by the tail read, or simply unprovable-as-having-written-since all read as finished, because a True *suppresses* a card — so it fails **open**, towards telling the person, and that is now true of the dominant case and not only the exotic ones. And the path is composed and then required to exist, so Grok and Codex never park on this rung.

**The path is composed from two strings a hook payload chose**, and the hook socket authenticates nothing beyond the project's enrolment key. So the open is `O_RDONLY | O_NONBLOCK` with the regular-file test on the **opened descriptor**: a FIFO left at that name blocks `open()` for ever on the asyncio loop — no SSE, no API, no hooks — and `sessions.json` would restore the state and re-hang it on the next start. A character device is refused by the same test rather than by size (`/dev/zero` reports `st_size` 0, so the tail seek would never fire). A NUL in either string is refused in `transcript_for`, because `stat()` raises `ValueError` on one and that is not an `OSError`.

**`_background_task_reason` is the fourth rung, and it is the third one's shape applied to the shell.** A `Bash` call with `run_in_background` returns at once — *"Command running in background with ID: … Output is being written to: …"* — and the harness **ends the turn**: the Stop hook fires, the transcript goes quiet, and the session is re-invoked by the harness itself when the command exits, the `<task-notification>` arriving as the next user record. Measured 20 Sep 2026 over this machine's 759 Claude Code transcripts: **399 of 2,038 Stops (20%) ended with a background task pending**, and the 133 resumptions that could be matched took a median of 116s and a p90 of 513s — every one a false *Waiting for input*. The run that prompted it sat under Needs you for two and a half minutes watching four CI runs.

`background_watch` reads two files. **The session's own transcript tail** (512 KiB, once per Stop, only when the first three rungs found nothing) says what is pending: every `tool_result` block whose text *begins* with the launch sentence — a session that quotes another's launch in a grep or a pasted log announces nothing — minus every later record carrying that task's `<task-id>`, because the notification *is* the resumption. **The task's output file** says whether it has come back: the harness appends `[exited with code N]` on exit, and every finished Bash output on this machine carried it. The file is opened only at the one name the harness writes — absolute, `…/tasks/<task id>.output` with the id the launch announced, no traversal — with the same `O_NONBLOCK` regular-descriptor test as the child transcripts, because the transcript is not Dark Army's file. **Nothing is stored between looks**: the transcript is the record of what was launched, the file the record of what finished, so a task that exits releases its session at the next card decision with no latch to expire. `PARK_MAX_SECONDS` (60 min) is the ceiling on being wrong — over a TestFlight archive, under the overnight outlier — and failure means *not running* in every form: no timestamp on the launch, an odd name, a missing or non-regular file. Grok and Codex end no turn on pending work (their journals carry neither sentence) and never park on this rung; a state with no `transcript_path` is untouched. The rung stamps `async_park_at` for the same reason its sibling does. Pinned by `test_background_task_parking.py`.

**A parked parent is exempt from staleness eviction while it is parked.** Parking leaves the state at `working` and raises no card, so `_waiting_on_human` says False and the 300-second evictor would take it — a session sitting out one silent seven-minute child would go to *Recently finished* with its ask still to come. `_parked_on_async_child` stamps `async_park_at` where the rung actually parked, and the exemption expires on `subagent_watch.STALE_SECONDS`, the same ceiling that releases the park itself. The two constants are coupled and this is where that is written down.

**The reading is a liveness test, not a latch, and the stamp is what makes it one.** "Has it written past its stop hook" is true for ever once it is true, so a child that worked for two minutes and then finished — with no terminal marker, which 42% of them have — would have gone on holding its parent until `STALE_SECONDS`: the very bug this rung exists to fix, moved to the other end of the run, and failing **closed** where everything else here fails open. So each park stores back the mtime it just observed as the child's next `since` (`running_ids` returns `{id: mtime}` for exactly this), and the next card decision asks for movement past *that*. The cost, stated plainly: a session whose async child is still writing has its genuine ask held back until the next card decision at which the file has not moved. Ids proven finished are dropped as they are read, which is also what bounds the file reading — only the first Stop after a burst of spawns walks more than a handful of names. **What re-asks it is the `idle_prompt` Notification**, not the parent's next Stop: `PARKED_CARD_HOOKS` is `("Stop", "Notification")` and that one fires ~60s into any quiet spell, so a child that finishes releases its parent within about a minute. That cadence is also why the 2s guard is safe rather than merely unlikely to bite — two decisions closer together than `WROTE_AFTER_STOP_SECONDS` would release a genuinely running child, and they are thirty times further apart than that; it is the fail-open direction in any case. Pinned by `test_async_subagent_parking.py`.

## A turn that ends on a work report is waiting on nobody

The two standing hints (`hooks.NOTIFY_SCRIPT`) give a Claude turn two ways to say who it is waiting on: `<!-- bob-tldr -->` / `<!-- bob-actions -->` mark a turn waiting on somebody (for the phone buzz, only a current `bob-actions` offer makes the turn a question — a `bob-tldr` alone reads as a finished turn, `alerts.offered_reply`), and a `## Work done` report marks a turn waiting on nobody. `session_stats.finished_quietly(transcript_path)` reads the closing assistant message — the last `assistant` record carrying a text block, a trailing tool-only record being the same turn still running — off a bounded tail (`CLOSING_TAIL_BYTES`, the `O_NONBLOCK` regular-file open `background_watch` uses) and answers True for a report with neither marker — or for the `/ship` close-out helper's line, `close-out: terminal left open` (`CLOSE_OUT_LEFT_OPEN`), which a plan or scout run ends its last message on whenever its terminal stays open (only `--plan` from a card's planning run, or a person's `--close`, closes one): a second quiet rung, the markers still vetoing it. `_handle_message`'s `add` path asks `_finished_quietly` once per Stop / Notification **after** the four parking rungs and **not as one of them**: a parked turn is still working, this one is done. A quiet finish raises no card, chimes nothing, drops an earlier card for the same session (the report supersedes it) and `_update_session_state(quiet=True)` writes `idle` whichever hook it was — a Notification's `confused` would otherwise bank the finished row under Needs you an idle-prompt later. The row sleeps instead of asking. Left exactly as they were: a report *with* a summary, a plain answer, no report at all, and every `StopFailure` (never a parked hook, never a quiet one). Claude only — the report hint is never printed to Grok and Codex runs no hook handler — and any doubt (no transcript path, unreadable, half-written) is False. Pinned by `test_quiet_finish.py`. Grok's finished demote already keys on the `close-out:` prefix. Codex gets the left-open line alone, narrowly: `parse_rollout` sets the private `CodexRecord.left_open` from the last assistant message (`session_stats.quiet_close_out`, reset by a real prompt), and `_reconciled_categories` files such a root — no question, not working, no helpers — under `sleeping`, its row's `state` `idle`; a Codex `## Work done` alone still asks, since Needs you is the only flag an unchecked Codex build gets. Pinned by `test_codex_rollouts.py`.

**A report can ask for a rebuild with one more line.** A fourth standing
instruction (`NEXT_STEP_HINT`) asks an agent whose finished work changed Dark
Army's own code to add `<!-- dark-army-next: rebuild -->` beside the `## Work
done` report. `session_stats` parses it in the same assistant message (`_NEXT_RE`,
closed vocabulary `NEXT_STEPS`) and only where the message carries a report: it
stamps `rebuild_marker_at`, **never `marker_at`**, so the row is not waiting on
anybody and `finished_quietly` is unchanged. The stamp belongs to the report: it
survives chatter and is cleared by the person's next genuine prompt, or
withdrawn by a newer report without the marker. `_enrich_agent_stubs` publishes
`rebuild_offered` (`rebuild_state.offered`) only for a row whose enrolled root
equals `enrollment.self_root()` exactly (a card worktree is not the own
checkout), while the Mac can rebuild, and until a successful rebuild that
*started at or after* the marker's clock (`rebuild-stamp.json`). Claude only.
Pinned by `test_rebuild_marker.py`.

**The report is structured for drawing, never for state.** `work_report.parse` (pure, no file) splits `last_report` into Asked / Changed / Verified / Unchecked / Card, `nothing_unchecked`, `why_not_automated`, `labelled` (False, headline empty, for an unlabelled report), `cut` and a one-line `headline` (`Changed: … · 2 verified · nothing unchecked`); `_enrich_agent_stubs` publishes it as `work_report` beside `last_report`, absent where there is none, and both clients draw it through `WorkReport`. `alerts.py` uses the headline as a Stop card's body when no summary was left, and in the `report` rule: one silent Mac banner "<who> finished" (`kind` `finished`) for a `sleeping` row whose report is fresh (quiet within `FINISHED_IDLE_GRACE_SECONDS`) with no card or prompt, once per report (one seen while muted, frontmost or carried by a card counts as delivered), re-armed when the report clears, outside the per-session cooldown both ways; `notifier.post` sounds no `finished` kind. No card, no chime, no inbox entry, no bucket, no buzz (`withheld:finished`). Pinned by `test_work_report_parse.py` and `test_alerts.py`.

**Mission Control's every reply is quiet, by origin rather than by transcript.** The standing chief-of-staff session (`mission.py`, `docs/context-host.md`) answers the question a person typed at it and waits for the next; that wait is not a request for the human. `_handle_message`'s `add` path asks `_mission_reply` **before** `_finished_quietly`, on the same site and with the same outcome: when the session's origin stamp — off `_session_states[sid]["origin"]`, else the stamp the message itself carries, since the state may not hold it on the very first Stop — parses to the kind `mission`, the Stop or Notification raises no card, chimes nothing, drops an earlier card, and `_update_session_state(quiet=True)` writes `idle`. The row sleeps under *Idle*, counts nowhere on the strip's attention figure, buys no push and no Live Activity, and is evicted on the ordinary 300-second clock like any quiet row (a card would have exempted it). Reads no file. **This is not a fourth place the daemon acts on a session**: like the parking rungs and the work-report rung it *withholds* a card and performs nothing — no keystroke, no banner, no eviction. `StopFailure` is never quiet here either. Pinned by `test_mission_control.py`.

## Staleness eviction

Sessions with no events within the timeout are evicted; the timeout is `preferences.DEFAULTS["session_timeout"]` = 300s, handed over once at startup. No sessions = sleeping.

## Liveness eviction

Sessions whose PID is gone are evicted immediately; sessions that never got a PID are evicted after a 90s grace (`PIDLESS_GRACE_SECONDS`). Sessions in the waiting bucket (`_waiting_on_human`, which asks `categorize()`) are exempt and fall through to wall-clock staleness.

**A Grok turn outlives its tab.** Grok's hooks run under the shared `grok agent leader`, a separate process, and a turn already running carries on when the terminal dies — VS Code's main process ran out of memory on 21 Sep 2026 and every tab went, while the session on the board-search card kept implementing, spawned its verifier and flagged its hand-check with no terminal at all. Grok drops the id from `active_sessions.json` with the tab, so the roster says gone and the hook grace (`GROK_ROSTER_GRACE_SECONDS`, 20 s) ran out on every wait for a subagent; Dark Army showed the card as ended and the row as finished, again on every hook. Both liveness paths — the roster pass (`_grok_hook_state_stays`) and the pidless eviction — now accept one more witness, `_grok_headless_turn_alive`: the row's last hook state is mid-turn (`working` / `thinking`) **and** the session's own directory, or a live child's (`grok_roster.last_activity` over `events.jsonl`, `updates.jsonl`, `chat_history.jsonl`), was written within `GROK_HEADLESS_GRACE_SECONDS` (5 min). A tab closed after Stop was last seen `idle`, so the witness does not apply and it ends at the roster grace as before. A row that stays while its id is absent from the roster publishes `tab_gone` — waiting, a pid that still looks like grok, a hook that just refreshed `last_event`, or that witness — except a never-listed id still inside the 20s roster lag. That lag is `busy_since` (set once at the start of the stretch); hooks rewrite `last_event`, so a fresh hook is not the lag. An id in the previous `_grok_records` has been listed. A return to the live roster clears the bool. A row the stay returns false for — its pid now belongs to another live session — is not stamped. Jump and the hosted terminal are withheld (`can_jump`, `own_terminal` and `can_terminal_input` false). `last_report`, lifted from `chat_history.jsonl` on the enrich pass, is the report both clients already draw. An idle row still ends at the roster grace, and the tombstone keeps the bool and the report. Pinned by `host/tests/test_grok_headless_turn.py`.

## Subagent tracking

`SubagentStart`/`SubagentStop` hooks track active `agent_id`s per session; a session with active subagents is never evicted and counts as "working". Grok's hook often has only `subagentType` and fires `SubagentStop` *inside the child*, so the converter prefers `subagent_id`, attributes start/stop to `parentSessionId`, and `_sync_grok_subagents` replaces a stale type-set from `chat_history.jsonl`. `subagent_spawns` is the timed companion to `subagents_seen` — `[role, at]` per start, never deduped, newest `MAX_SUBAGENT_SPAWNS` kept, persisted with the state and dropped on restore when it is not a list — read by `_record_card_stages` to fill a batch member's trail from its own window alone.

## Finished sessions

`_finished`, `FINISHED_RETENTION_SECONDS` = 30 min. Every removal path routes through `_forget_session(sid, reason)`, which leaves a tombstone so *Recently finished* can still show what a run cost. Codex has no hook stream to forget, so `_settle_codex_stop` and `_refresh_codex_records` write the tombstone themselves; `_collect_agent_stubs` emits **one row per session id**, first source winning. `finished_at` is the session's `last_event`, **not** the removal time. The `finished` bucket is assembled in `_enrich_agent_stubs`, **not** in `_reconciled_categories()`, and also holds live sessions quiet past `FINISHED_IDLE_GRACE_SECONDS` (2 min), flagged `alive`, so the panel's `idle` KPI = Sleeping + the live rows here. Background agents are tombstoned on vanishing from `claude agents --json`. Finished entries are excluded from signal evaluation. In memory only — a restart forgets.

## Silence is not a lost session

`board_queue.needs_you` is the daemon's own "this card lost its assistant" bit — the Inbox's `endedWork`, and on the phone the *CARDS WITHOUT A SESSION* band with **Mark done** and **Send back** beside it. Its quiet-live rung asks `_claiming_session_ids()`, whose only evidence is hook-stream freshness, and a session emits no hook for the whole of one long tool call: five quiet minutes inside a build or a test run evicts it while its terminal, its process and its work stand exactly where they were. The queue can afford that reading (a wrong "gone" frees a slot early); this cannot, because what it publishes invites a person to bury work still being done. Measured 7 Sep 2026: a dispatched implementation session went quiet at 08:56, was evicted at 09:01:50, its card appeared under Needs you, and it left again on the next hook.

So the rung asks one more thing: that the last state Dark Army saw was the **end** of a turn. `_mid_turn_quiet_ids()` reads the tombstones `_forget_session` leaves and keeps those whose `end_reason` is **`evicted`** alone — wall-clock staleness, the removal this file already calls a statement about Dark Army's bookkeeping rather than about the tab, and never `no process`, which is a real end — and whose frozen state is in `board_queue.MID_TURN_STATES` (`working`, `thinking`). One reading per frame beside `active`, passed into both `_decorate_card_for_snapshot` and `_needs_you_drifted` so the published bit and the frame it buys cannot disagree. The intended case is untouched: a session that finished its turn and went quiet with its terminal open was last seen `idle`, so its card still asks for a person, and the tombstone's own 30-minute retention is the bound past which silence alone is answer enough. Pinned by `host/tests/test_needs_you_cards.py`.

## Auto-compact

`autocompact.py` decides, the daemon types. `ctx-full` fires at `signals.CTX_CRIT_PCT` — 85%, from 90% on 25 Sep 2026, the Strands Harness default (`docs/harness-token-policy.md`), which the clients' red context figure and the card's health line (`run_health.CTX_WORRY_PCT`) match, pinned by `test_signals.py`. A session whose `ctx-full` signal is up — or `ctx-runway` at `crit` — in a VS Code window on extension 0.1.6+ gets `/compact` typed onto its **input line** (`send_text` → `Terminal.sendText`, no `.show()`), and the signal is marked `handled`. **The channel cannot carry this**: Claude Code and Grok expand `/compact` on the input line. **Codex is excluded before reachability probing and policy consideration**, and delivery re-resolves the provider and refuses known Codex records/ids. **One attempt per episode**: after `SETTLE_SECONDS` (180s) the warning has gone or the session is handed back to the alert path; a send that matches no terminal re-arms at once (`note_failed`); an episode is popped after `CLEAR_SECONDS` (30s) of absence. Decided on the executor (`_decide_auto_compacts`), typed on the loop (`_flush_auto_compacts`). Preference `auto_compact`, default on, inert without a 0.1.6+ window.

## Alerts

`alerts.py` decides, `dark_army_menubar/notifier.py` delivers. A signal is evaluated every few seconds to be *shown*; an alert fires once, on a transition, to be *delivered*. The policy is pure — transitions only, `waiting` and `crit` only, one per agent per `PER_SESSION_COOLDOWN`, per-session mute, suppressed while that session's VS Code window is frontmost. **A relayed permission prompt rides the same evaluation** (`_prompts_by_session()` feeds `AlertPolicy.evaluate`) under harder rules: no cooldown, no waiting-category gate, dedupe on the request id once ever (`clear_resolved` skips `permission:` keys); the banner is "\<nickname\> wants to run \<tool\>" with actions `reveal`/`mute` only. Suppression works because the extension answers it — `vscode_reveal.frontmost_session_pids()` is a `frontmost` op (extension 0.1.4+), polled on its own 4s timer, trusted for 15s, every failure path returning the empty set. `_alerts` is a bounded record of what was decided; `_undelivered` is a **debt** drained by `_deliver_alerts()` *after* the agents snapshot is pushed — drained once; the banner leg posts at once, and the phone leg of a `card`-rule alert may wait `PUSH_GRACE_SECONDS` on the loop and re-check `_active_notifications[sid]` before its POST, dropping when the card is gone — the one place a drained alert is looked at again, stated in `docs/transport-contract.md`, *The phone leg is filtered, gated and held*.

## Where a session came from

`origin` is a session-state key and nothing else: the `BOB_COMPANION_ORIGIN` the hook handler carried, written **once** and never overwritten. Dark Army stamps it into a terminal's environment at the spawn (`origin.py`, `dispatch.spawn` / `spawn_local`), the handler carries it on **every** message the way `key` is — a `SessionStart` dropped while the daemon was restarting must not leave that session unattributed for ever — and `_update_session_state` records it first-writer-wins, a `session_start` carrying its predecessor's value across the one branch that replaces the dict whole. `_record_finished` copies it onto the tombstone, so a row keeps saying where it came from after `_forget_session` has popped its state. It is published as the row's `origin_by` / `origin_card` / `origin_line`, **all three absent** where there is no stamp — and the raw stamp itself never rides the published entry — and `origin.sentence()` composes that line on the daemon so both clients draw it verbatim. Persistence needs no migration: `save_sessions` writes every key and `load_sessions` keeps unknown ones, so an older build reads past it and a downgrade loses only the line. **It is an attribution boundary, not authentication** — a forged stamp grants nothing and every capability gate is untouched; a *missing* stamp is the honest default and draws nothing. **A Grok row is stamped off its own process, never off its hook**: Grok runs its hooks under the shared `grok agent leader`, whose environment is the terminal that first started it, so the stamp on a Grok message names whichever card *that* terminal was for (21 Sep 2026: one dark-army card on every Grok row for ten hours). `_handle_message` passes a Grok message's stamp as empty and `_probe_grok_origin` reads `BOB_COMPANION_ORIGIN` off the session's own pid (`pid_resolver.process_origin`, one `ps -E` in the executor, once per session and pid) — the one place `origin` is rewritten: replaced by the process's stamp, or cleared where the process carries none. Pinned by `test_session_origin.py`.

## Session persistence

State is saved atomically to `~/.dark-army/sessions.json` on structural changes and loaded at startup with immediate stale eviction. **The question a session is stopped on rides in the same envelope**, under its own `pending_questions` key, outside the state machine: an `AskUserQuestion`'s text reaches the transcript only alongside its *answer*, so the `PreToolUse` hook is the sole reader while the dialog is up. `_restore_pending_questions` takes one back only if its session survived the startup prune **and** came back `waiting`; the slot self-corrects on the next event (`QUESTION_CLEARING_EVENTS`), and `_track_pending_question` writes through on any change. **Dark Army answers a dialog by keystroke, and the burst follows the client's widgets, read out of the installed CLI** (`answer_question` / `answer_questions` → `_type_answer_burst`): a pick-one question is its digit alone (`PICK_ONE_SUBMIT_KEYS`, empty — the digit selects and advances), a `has_preview` pick-one is digit then Enter (`PREVIEW_PICK_ONE_SUBMIT_KEYS`), a `multi_select` question is its digits then `MULTI_SELECT_SUBMIT_KEYS`, and the burst ends with one Enter wherever the client shows its "Review your answers" screen — `_dialog_has_summary`: every shape but a single pick-one question. Both flags are strict bools carried per question by the hook script and `session_stats`, defaulting to False. A CLI bump re-reads the dialog before trusting any of the tuples.
